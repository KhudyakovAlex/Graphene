# AI Usage Guide

Этот документ читает AI, который создает интерфейс приложения с использованием Graphene.

Цель: не рисовать интерфейс с нуля, а собирать его из правил, стилей и компонентов Graphene.

## Перед Началом

1. Установи Graphene по immutable Git tag: `npm install "github:KhudyakovAlex/Graphene#v0.3.0"`.
2. Подключи глобальные стили через `import '@graphene/core/styles.css'`.
3. Импортируй компоненты и типы только из `@graphene/core`.
4. Импортируй SVG-иконки по имени только из `@graphene/core/icons/*.svg?url`.
5. Не импортируй внутренние файлы пакета из `src/` или `dist/`.
6. Используй IBM Plex Sans из CSS Graphene, не подключай внешний шрифт.
7. Не создавай локальные аналоги компонентов Graphene без необходимости.

Публичный API consumer-приложения ограничен package entrypoints:

- `@graphene/core` — компоненты и TypeScript-типы;
- `@graphene/core/styles.css` — токены, глобальные стили и локальные шрифты.
- `@graphene/core/icons/*.svg` — основной набор SVG-иконок;
- `@graphene/core/icons/others/*.svg` — резервный набор SVG-иконок.

## Как Верстать

Используй уровни Graphene по порядку:

1. Семантические CSS-токены из подключенных стилей.
2. Базовый внешний вид из `@graphene/core/styles.css`.
3. Готовые Vue-компоненты из `@graphene/core`.
4. Offline-витрина репозитория — примеры правильного применения.

`examples/index.html` находится в репозитории Graphene и не входит в устанавливаемый пакет.
Внутри репозитория витрина может импортировать исходники Graphene напрямую, но consumer-приложение всегда использует только публичные package exports.

Если есть компонент Graphene, используй его.
Если компонента нет, используй обычную HTML-разметку со стилями Graphene и семантическими токенами.
Не копируй разметку и стили компонента из витрины в приложение.

Текущие базовые компоненты:

- `BaseButton` - использовать для основных и вторичных действий;
- `BaseLink` - использовать для текстовой навигации внутри текста или отдельной строкой; использует `--g-link-*`;
- `BaseCheckbox` - использовать для одиночного boolean-переключателя без встроенного label;
- `BaseSwitch` - использовать для on/off переключателя; использует `--g-switch-*`;
- `BaseRadio` - использовать для одного варианта в radio group; встроенного label нет;
- `BaseInput` - использовать для простого текстового ввода; правую зону действия передавать через slot `trailing`.
- `BaseSelect` - использовать для выбора одного или нескольких значений из списка; визуально следует `BaseInput` и использует `--g-field-*`.
- `BaseSlider` - использовать для одиночного выбора значения на шкале; использует `--g-slider-*` и не содержит встроенный label.
- `BaseTextarea` - использовать для многострочного текстового ввода; визуально следует `BaseInput` и использует `--g-field-*`.

Текущие layout-компоненты:

- `Surface` - использовать для surface-контейнеров, секций и рабочих областей; использует `--g-surface-*` semantic tokens для фона, формы и адаптивных внутренних отступов. `Panel` остается временным deprecated-алиасом.

Текущие data-компоненты:

- `DataTable` - использовать для простых readonly-таблиц с колонками и строками; по умолчанию работает в `layout="fit"` без горизонтальной полосы прокрутки, поддерживает opt-in `layout="scroll"`, column `overflow="ellipsis" | "wrap"`, встроенные строки `section` и `total`, runtime `textColor` для строк и slots для кастомных header/cell.
- `DataGrid` - использовать для интерактивных таблиц, когда нужны сортировка, фильтры, скрытие колонок и изменение их ширины; построен поверх `DataTable` и подходит для реестров, журналов и рабочих списков.
- `DataList` - использовать для плоского списка записей с основным текстом, supporting-текстом и метаданными строки; подходит для журналов, событий и списков сущностей.
- `PropertyList` - использовать для readonly-показа свойств объекта в формате `label/value`; сам не добавляет surface и хорошо подходит для `Surface`, `BaseDialog` и страниц деталей.

Для таблиц придерживайся простого правила:

- если нужна только визуальная таблица, бери `DataTable`;
- если таблице нужно состояние колонок и интерактивный toolbar, бери `DataGrid`;
- не копируй интерактивный table-UI локально, если его уже можно собрать на `DataGrid`.

Текущие feedback-компоненты:

- `BaseDialog` - использовать как базовую модальную оболочку для подтверждений и форм редактирования; использует `--g-dialog-*`.
- `ConfirmDialog` - использовать для подтверждения удаления, закрытия без сохранения и других бинарных решений; построен поверх `BaseDialog`.
- `FormDialog` - использовать для create/edit форм с типовым footer `Cancel/Submit`; построен поверх `BaseDialog`, а поля формы передаются через default slot.

Отступы и gap диалогов нужно брать из доступных semantic CSS-переменных Graphene, а не из base spacing напрямую.

Для `BaseInput` с иконкой справа используй slot `trailing`.
Импортируй нужную иконку как URL, например `@graphene/core/icons/search.svg?url`, и передавай ее через разметку slot. Для редких сценариев доступен резервный путь `@graphene/core/icons/others/<name>.svg?url`.
Сначала выбирай иконку из основного набора. Не копируй каталог иконок в consumer-репозиторий: Graphene поставляет оба набора локально, а Vite включает в production bundle импортированные SVG.
`BaseInput` отключает нативный browser clear-крестик у `type="search"`, чтобы справа отображались только элементы Graphene.

По умолчанию не добавляй скругления.
Базовая форма Graphene - прямоугольная, ближе к IBM Carbon.
Используй `--g-radius-none`, если нет явного правила или макета со скруглением.

## Запреты

Нельзя:

- подключать CDN;
- подключать внешние шрифты;
- использовать случайные цвета, если есть семантический токен;
- задавать произвольные отступы, если есть spacing token;
- писать inline styles без сильной причины;
- копировать код из `examples` как отдельную дизайн-систему;
- делать интерфейс только под широкий десктоп.

## Темы

Интерфейс должен работать в светлой и темной теме.

Переключение темы ожидается через:

`data-theme="light"`

или:

`data-theme="dark"`

Используй семантические токены, например `--g-text-primary`, а не базовые цвета вроде `--g-gray-950`.
Не меняй семантические токены Graphene и их привязку к базовым токенам в коде ради локального совпадения конкретного компонента или экрана.
Не добавляй новый semantic token в код вручную. Если роли не хватает, сначала попроси добавить ее в Pixso.
Если токен не соответствует Pixso, скажи владельцу, какой semantic token нужно поправить в Pixso.
После правки в Pixso синхронизируй токены из Pixso в код, не выбирая base tokens вручную.

## Устройства

Интерфейс должен работать на десктопах, планшетах и телефонах.

Учитывай:

- портретную ориентацию телефона;
- touch-размеры интерактивных элементов;
- отсутствие лишнего горизонтального скролла;
- корректную работу меню, таблиц и модальных окон на узком экране;
- полноэкранную оболочку приложения.

## Offline/Intranet

Приложение должно работать без внешнего интернета.

Все шрифты, ассеты и runtime-зависимости должны быть локальными или доступными во внутреннем контуре организации.
Не импортируй внутренний каталог иконок Graphene из `src/`: используй публичные пути `@graphene/core/icons/*`.
Иконки физически находятся в установленном пакете Graphene и переносятся Vite в dev/production output; хранить их копию в Git consumer-приложения не требуется.
SVG-иконки используют `currentColor`, поэтому цвет задавай через CSS и semantic tokens, а не через правку SVG.
